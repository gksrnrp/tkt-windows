# tkt (terminal kakao talk)

터미널에서 카톡을 주고받을 수 있는 TUI (Text User Interface)

![tkt example image](https://github.com/user-attachments/assets/b638804a-516a-4752-8996-9f59d8e8d857)

> ❗중요❗
> - 개인 환경에서만 테스트를 진행했어요. 다른 환경에서는 의도와 다르게 동작할 수 있어요
> - 카카오톡 UI의 변경에 따라 동작하지 않을 수 있어요
> - 카카오가 공식으로 허용한 방식이 아니니 사용 방식에 따라 카카오 이용약관 또는 운영정책 위반으로 해석될 수 있어요
> - **macOS와 Windows에서 동작해요** (Linux는 카카오톡 데스크톱 앱이 없어서 불가능해요)

## 시작하기 전에
### 필요사항

**공통**

| 항목 | 이유 |
|---|---|
| Node 20 이상 | npm을 사용해요 |
| 카카오톡 데스크톱 앱 | 로그인 + 채팅창 열림 상태 |

**macOS**

| 항목 | 이유 |
|---|---|
| macOS 13 이상 | 카카오톡 Mac 앱과 접근성 API를 위해 필요해요 |
| Xcode Command Line Tools | `swiftc` 로 네이티브 헬퍼를 빌드해요 (`xcode-select --install`) |
| 터미널의 손쉬운 사용 권한 | 접근성 API를 쓰려면 필요해요 |

**Windows**

| 항목 | 이유 |
|---|---|
| Windows 10 이상 | 카카오톡 PC 앱을 위해 필요해요 |
| .NET Framework 4.x | `csc.exe` 로 네이티브 헬퍼를 빌드해요. Windows에 기본으로 들어 있어서 따로 설치할 게 없어요 |

별도 권한 설정은 없어요. 다만 카카오톡을 **관리자 권한으로 실행하면 안 돼요** — 일반 권한
터미널에서는 그 창을 건드릴 수 없어요.

### 동작 원리

카카오톡 공식 API를 쓰지 않고, 데스크톱 앱의 UI를 직접 읽고 조작해요. 그래서 플랫폼마다
방법이 달라요.

**전송 (두 플랫폼 공통)**
- 입력창의 내용을 보내고자 하는 메시지로 치환하고 전송해요
- 카카오톡 창을 앞으로 끌어올리지 않아요
  - macOS: 전송 버튼을 직접 눌러요
  - Windows: `EM_REPLACESEL` 로 본문을 넣고 입력창에 Enter 키 메시지를 직접 꽂아요

**읽기 (macOS)**
- Accessibility API로 채팅창에서 시각, 보낸 사람, 본문을 읽어요
- 말풍선이 오른쪽 끝에 붙어 있으면 내가 보낸 것으로 간주해요

**읽기 (Windows)**
- 카카오톡 PC는 대화 내용을 **접근성 API에 전혀 내놓지 않아요.** UI Automation으로 열면
  자식이 스크롤바뿐이고 지원하는 패턴이 하나도 없어요. 레거시 MSAA도 마찬가지예요
- 그래서 앱이 직접 만들어주는 복사 결과를 씁니다 — 대화 목록에 `Ctrl+A` → `Ctrl+C` 를
  보내고 클립보드에서 받아와요. 카카오톡이 `[이름] [오후 3:22] 본문` 꼴로 만들어주니
  보낸 사람과 시각이 정확해요
- 창을 앞으로 끌어올리지 않아요. 카카오톡 프로세스 안쪽 포커스만 잠깐 옮겨요

> **Windows에서 알아둘 점**
> - 읽을 때마다 **클립보드를 잠깐 빌려요.** 원래 내용은 되돌려 놓지만, 되돌릴 수 있는 건
>   텍스트뿐이에요. 클립보드에 이미지나 파일이 들어 있었다면 그건 잃어요
> - 클립보드를 붙잡고 있는 프로그램(일부 클립보드 관리 도구)이 있으면 읽기가 실패해요
> - 그래서 읽기 주기가 macOS(1초)보다 길어요 — 기본 3초
> - **내가 보낸 메시지를 구분하려면 본인 이름이 필요해요.** 복사본에는 내 메시지도 내
>   이름으로 적히거든요. 처음 실행할 때 한 번 물어봐요
> - **카카오톡 자동 잠금을 꺼두는 걸 권해요.** 카카오톡은 일정 시간 앱을 만지지 않으면
>   잠기는데, 잠기면 열어둔 채팅방 창이 **모두 닫혀요.** tkt 로 대화하는 동안에는 카카오톡을
>   직접 만지지 않으니 카카오톡 입장에서는 자리를 비운 것으로 보여요. tkt 가 잠금 상태를
>   알아채서 알려주긴 하지만, 계속 쓰려면 카카오톡 설정에서 자동 잠금을 꺼야 해요
> - 읽기가 `Ctrl+A` 로 대화를 전체 선택하기 때문에, 카카오톡 창을 보면 대화가 선택된 채로
>   남아 있어요. 선택을 지우려면 `Esc` 를 보내야 하는데 그건 채팅방 창을 닫아버려서
>   그냥 두는 쪽을 골랐어요. 카카오톡 창에서 아무 곳이나 클릭하면 풀려요
> - 닫혀 있는 채팅방을 대신 열어주지 못해요. 채팅 목록도 접근성에 노출되지 않아서 방을
>   짚을 수가 없어요. 쓰려는 방은 카카오톡에서 직접 열어두세요

**공통 제약**
- 채팅방은 **창 제목**으로 구분해요. 이름이 겹치는 방이 여럿이면 아무것도 하지 않아요
- 카카오톡 UI가 한국어 또는 영어인 경우만 동작해요
  - 다른 언어라면 `native/tkt-ax.swift`(macOS)의 `chatListWindowTitles`, `sendButtonTitles`
    또는 `native/tkt-win.cs`(Windows)의 `MainWindowTitles` 를 고쳐야 해요

## 실행
- **실행하기 전 채팅을 주고받고자 하는 카카오 채팅방을 미리 열어두세요**
```bash
npm install
npm run dev
```

처음 실행하면 열려 있는 채팅방 중에서 대상을 고르게 해요. 나중에 바꾸려면:

```bash
npm run dev setup
```

## 사용법
| 키 | 동작 |
|---|---|
| `Enter` | 전송 |
| `Tab` | 채팅방 전환 (열려 있는 카카오톡 채팅창 중에서) |
| `Esc` | 종료 |

## 문제가 생기면

```bash
npm run doctor
```

어느 단계에서 막히는지 순서대로 짚어줘요. 네이티브 헬퍼를 직접 불러볼 수도 있어요.

```bash
# macOS
./native/tkt-ax check
./native/tkt-ax windows
./native/tkt-ax read "채팅방 이름" 5
```

```bash
# Windows
.\native\tkt-win.exe check
.\native\tkt-win.exe windows
.\native\tkt-win.exe read "채팅방 이름" 5 "내 이름"
.\native\tkt-win.exe raw "채팅방 이름"     # 복사된 대화 원문 (파싱 전)
.\native\tkt-win.exe probe "채팅방 이름"   # UI 트리 덤프
```

카카오톡 버전이 올라가 읽기가 깨졌다면 `raw` 로 복사 형식이 바뀌었는지, `probe` 로 창
클래스 이름이 바뀌었는지 확인하는 게 빨라요.
